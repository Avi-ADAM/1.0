נבדק בפרודקשן ב-`https://www.1lev1.com` בתאריך **2026-08-12**, עם דפדפן אמיתי
(Chromium/Playwright) ומשתמש בדיקה **קלוד בודק** (`babayofnet+5899@gmail.com`,
`userId = 256`). נוצרה ריקמה חדשה — **"ריקמת בדיקה קלוד"** (`projectId = 82`) —
ועברנו על כל מסלול הניהול שלה כאשר יש בה **חבר אחד בלבד**.

הבדיקה כיסתה: יצירת ריקמה · עריכת פרטים · יצירת משימה · לקיחת משימה על עצמי ·
טיימרים והתקדמות · סיום משימה · יצירת משאב והשמה עצמית · אישור קבלת משאב ·
יצירת מוצר · דיווח מכירה (כולל "אצל מי הכסף") · הצעת חלוקה · דף החלוקה ·
דף התמיכה הציבורי · דף הפרויקט הציבורי · לוחות (קאנבן/גאנט/שרשראות/משמרות) ·
עמוד ההצבעות · הלב.

**שורה תחתונה:** רוב המסלולים עובדים, ויש מסלולי solo ייעודיים שנבנו נכון

## חוסמים (Blockers)

### B1 · ריקמת אדם אחד לא יכולה לבצע חלוקה — `createTosplit` נכשל תמיד

**מה קורה:** בעמוד `כסף → מכירות`, אחרי דיווח מכירה, לוחצים
"צפיה בהצעת החלוקה" ואז "אישור ובקשת חלוקה". החישוב מוצג נכון
(100% אחוז ברקמה · 500 החלק מהרווח · 500 אצלי · **מאוזן**), אבל הבקשה נכשלת:

```
POST /api/action  { actionKey: "createTosplit", params: { data: {
  project: "82",
  vots: [{ what: true, users_permissions_user: "256" }],
  halukas: [],                       ← ריק, כי אין למי להעביר
  hervachti: [{ users_permissions_user: 256, amount: 500, ... }],
  sales: [104] } } }
→ 400 {"success":false,"error":{"code":"VALIDATION_FAILED",
        "message":"Parameter validation failed",
        "details":["Parameter data failed custom validation"]}}
```

**למה:** `src/lib/server/actions/configs/createTosplit.ts` דורש
`halukas.length > 0`:

```ts
if (!Array.isArray(value.halukas) || value.halukas.length === 0) return false;
```

בריקמה של אדם אחד הכסף כבר אצל החבר היחיד, ולכן מספר ההעברות הוא **אפס
לגיטימי** — ה-UI עצמו כותב "מאוזן". הוולידציה חוסמת בדיוק את המצב התקין הזה.

**התוצאה:** המכירה נשארת לצמיתות תחת "הכנסות ממתינות לחלוקה", `sale.splited`
לא מתעדכן, ואין שום דרך ב-UI לסמן את ההכנסה כמחולקת. זה שובר את כל התמונה
הכספית של ריקמת יחיד (וגם את "כבר חולק לעושים" בדף התמיכה, שנשאר ₪0).

**כיוון תיקון:** להתיר `halukas: []` כשה-`hervachti` לא ריק (חלוקה "מאוזנת"),
או מסלול solo ב-`createTosplit` שמסמן את המכירות כמחולקות בלי ליצור העברות —
במקביל למסלולי ה-solo שכבר קיימים ב-`applyToMission` / `completeMission`.

**חומרה: חוסם** — פונקציונליות ליבה שלא ניתן לעקוף.

### B2 · לקיחת משימה על עצמי נכשלת (500) כשלמשימה יש תיאור — GraphQL escaping

**שחזור:** יוצרים משימה עם תיאור (עורך ה-RichText תמיד מפיק
`<p style="text-align: right;">…</p>`), נכנסים ל-`/availableMission/<id>`
ולוחצים "אני אשמח לבצע!".

```
POST /api/action { actionKey: "applyToMission",
                   params: { openMissionId: "246", projectId: "82" } }
→ 500 {"success":false,"error":{"code":"INTERNAL_ERROR",
        "message":"An unexpected error occurred"}}
```

אותה משימה בדיוק, **בלי תיאור**, עוברת:
`{"success":true,"data":{"mesimabetahalichId":"185","solo":true}}`.

**למה:** `src/lib/server/actions/configs/applyToMission.ts` (מסלול ה-solo,
סביב שורה 232) בונה מוטציה ע"י אינטרפולציה של מחרוזות לתוך ליטרלים של GraphQL
בלי escaping:

```ts
hearotMeyuchadot: "${omAttrs.hearotMeyuchadot ?? ''}",
name: "${omAttrs.name ?? ''}",
descrip: "${omAttrs.descrip ?? ''}",      // ← ה-" שבתוך style="…" שובר את המוטציה
publicklinks: "${omAttrs.publicklinks ?? ''}",
```

מספיק גרש כפול אחד (או שורה חדשה) בשדה כדי לשבור את השאילתה. זה גם וקטור
הזרקת GraphQL, לא רק תקלת תצוגה.

**אותו דפוס קיים גם ב:**
- `src/lib/server/actions/configs/finalizeAskAcceptance.ts:148-155` — כלומר
  **גם המסלול הרב-משתתפי** (קבלת מועמד למשימה) נשבר על תיאור עם גרשיים.
- `src/lib/server/actions/configs/voteOnMaap.ts:371` (`name:`).

**התיקון כבר קיים בקוד:** `finalizeJoinAcceptance.ts:186-188` משתמש ב-block
strings של GraphQL (`"""…"""`), ו-`voteOnPendm.ts:169` / `voteOnPmash.ts:157`
עושים `.replace(/"/g, '\\"')`. צריך רק להחיל את אותו טיפול על שאר הקבצים —
ועדיף לעבור למשתני GraphQL אמיתיים.

**בונוס:** ה-UI **לא מציג שום שגיאה** על ה-500. הכפתור פשוט לא עושה כלום.

**חומרה: חוסם.**

### B3 · שאילתת GraphQL גולמית נחסמת ב-403 בכל עמוד באתר

בכל עמוד שנטען (הלב, מוח, פרופיל, ציבורי) יורה:

```
POST /api/send {"data":{"query":"{ usersPermissionsUser (id:256) { … } }"}}
→ 403 {"message":"Raw GraphQL queries are not allowed; use a queId"}
```

**המקור:** `src/lib/stores/pendMisMes.js:83` — `initialForum(all = true)` בונה
שאילתה גולמית במקום qid. בפרודקשן `/api/send` חוסם raw GraphQL (dev-only),
ולכן הקריאה נכשלת **תמיד**.

**מה נשבר בעקבות זה** (הכל מוזן מאותה תשובה):
- `forum` — רשימת הצ׳אטים/פורומים של המשתמש;
- `isChatLoading` — נדלק ל-`true` לפני הקריאה ולא מכובה במסלול הכשל;
- `username`, `uPic` — שם המשתמש ותמונת הפרופיל הגלובליים;
- `userProjects` — רשימת הריקמות של המשתמש בסטור.

**התיקון:** להעביר את השאילתה ל-qid ב-`src/routes/api/send/qids.js` (היא
מושכת `projects_1s → forums → messages` + `halukasres`/`halukasend`).

**חומרה: חוסם** (פיצ׳ר שלם — צ׳אט — לא נטען, בכל משתמש ובכל עמוד).

## באגים

### R1 · אחרי סיום משימה ב-solo, ה-UI מציג "⏳ ממתין לאישור" — אף שהמשימה הושלמה

`completeMission` מזהה נכון `noofpu === 1` ויוצר **`finnishedMission`** ישירות
(`{"createdType":"finnishedMission","createdId":"81"}` — נבדק פעמיים). אבל
מיד אחרי השליחה השורה בעמוד `עשייה` מקבלת באדג' "⏳ ממתין לאישור", והטוסט הוא
`moach.progress.sentForApproval` ("נשלח לאישור"). רק רענון מגלה שהמשימה בארכיון
"משימות שהושלמו". `/moach/82/object/finiapruval` ריק — אין למה לחכות.

`src/lib/components/mission/MissionControls.svelte:295-297` — צריך להסתמך על
`result.data.createdType` ולהציג "הושלם" במסלול ה-solo.

### R2 · `NaN` במחשבון החלוקה כשלריקמה עוד אין שווי צבור

בריקמה חדשה (או אחרי משימה שהסתיימה עם 0 שעות), עמוד `כסף → חלוקה` מציג:

```
שם            קלוד בודק
החלק מהרווח   NaN
אחוז בפרויקט  NaN%
```

`src/lib/components/prPr/hachcal.svelte:16` — `percentage()` היא
`(100 * partial) / total` בלי הגנה על `total === 0`; `0/0 → NaN`, וה-NaN זולג
דרך `p` גם ל-`x[i] = ((p/100) * revach).toFixed(2)`. אחרי שנצבר שווי אמיתי
הטבלה מציגה נכון (100.00% / 1000.00), כך שזה בדיוק מצב "ריקמה חדשה" — כלומר
מה שכל משתמש חדש רואה ראשון.

### R3 · תיאור המשימה מוצג כקוד HTML גולמי בדף התמיכה הציבורי

`/project/82/support` מציג תחת "מה עוד מחכה שיעשו אותו":

```
<p style="text-align: right;">עיצוב לוגו וזהות חזותית בסיסית לריקמה, כולל שני סבבי תיקונים.</p>
```

הטקסט של התגיות מוצג למבקרים כפשוטו.
`src/routes/(regandnon)/project/[id]/support/+page.svelte:295` —
`{om.attributes.descrip}` במקום `{@html …}` או `htmlExcerpt()` (ה-helper כבר
קיים ב-`$lib/text/htmlExcerpt` ומשמש ב-`bethas.svelte`). שאר הדפים הציבוריים
(`/project/[id]`, `/availableMission/[id]`) מציגים נכון.

### R4 · דיאלוג "עריכת הטיימר" ללא טיימר — משפט שבור עם אנגלית באמצע

לחיצה על "✎ עריכת הטיימר" במשימה שאין לה טיימר פותחת:

> "הטיימר נעצר לאחר **No timer available**. האם ברצונך לשמור את הזמן או
> לנקות אותו?"

fallback באנגלית מוזרק לתוך משפט בעברית, והדיאלוג מציע לשמור זמן שלא קיים.
צריך מצב ריק אמיתי (או להשבית את הכפתור כשאין טיימר).

### R5 · הודעת השגיאה בבקשת חלוקה — כפולה, ובשפה של המערכת

בבדיקה חוזרת ממוקדת (צילום ה-DOM 0.8 שנייה אחרי הלחיצה) התברר שה-UI **כן**
מציג שגיאה — פשוט הספיקה להיעלם עד ה-dump המקורי. אבל מה שמוצג הוא:

```
["Parameter validation failed", "Parameter validation failed"]
```

שתי הודעות זהות — אחת מ-`executeAction` (`showErrorToast` דלוק כברירת מחדל)
ואחת מ-`whowhat.svelte` שמדפיס את `error.message` הגולמי — ושתיהן מנוסחות
בשפה הפנימית של שכבת הפעולות, לא בשפה של המשתמש. בקונסול, אגב, יושבת דווקא
ההודעה הידידותית ("Invalid input. Please check your data and try again").

לשם השוואה, דיווח מכירה בלי "אצל מי הכסף" מחזיר הודעה טובה ומדויקת
("שדה אצל מי הכסף נשאר ריק") — זו הדוגמה שכדאי להכליל.

### R6 · אין ניהול למוצר שנוצר — אי אפשר לערוך או למחוק

בעמוד `כסף → מכירות`, לכרטיס מוצר יש רק שיתוף ו"דיווח על מכירה". טעות בשם או
במחיר נשארת לנצח (בבדיקה נוצר בטעות מוצר בשם "500" — אין שום דרך להסיר אותו).
בריקמת יחיד, שבה אין למי לפנות, זה בולט במיוחד. גם התיאור שהוזן בטופס
(`desc`) לא מוצג בכרטיס בשום מקום.

### R7 · ערך ללא תרגום מוצג כמזהה באנגלית

בטופס יצירת הריקמה, ברשימת "ערכים ומטרות" יש ערכים ללא לוקליזציה
(`altroisem`, `anarchy` — `localizations: { data: [] }` ב-`baciFormData`).
הם נבחרים ואז מוצגים כך בממשק העברי — בטופס, בעמוד `ראשי`, ובדף הציבורי
תחת "✨ הערכים שלנו". צריך fallback לשם מתורגם או סינון ערכים ללא תרגום.

### R8 · עמוד "משמרות" — טקסטים באנגלית

`/moach/82/shifts` מציג `today`, `all-day`, `Previous week`, `Next week`
(רכיב `@event-calendar`) בתוך ממשק עברי, לצד ההודעה "בפיתוח נמרץ".

## הערות נגישות ו-i18n

### A1 · פקדים ראשיים הם SVG שאינם נגישים מהמקלדת
- "הוספת משימה" — `<g id="button" onclick={hosa}>`
  (`src/lib/components/prPr/hand.svelte:151`);
- "בקשת משאב" — `<a id="newbutton" onclick={bighand}>` בלי `href`
  (`src/lib/components/prPr/handd.svelte:374`).

ל-`<g>` ול-`<a>` ללא `href` אין `role`, אין `tabindex` ואין שם נגיש (רק
`<title>`) — הם אינם ניתנים למיקוד, ל-Tab או ל-Enter. אלו שני הפקדים הכי
מרכזיים בעמוד "יצירה".

### A2 · כפתורי אייקון ללא שם נגיש
- כפתור **אישור קבלת משאב** בכרטיס הלב — כפתור אייקון ריק לגמרי, בלי טקסט
  ובלי `aria-label`. זו הפעולה היחידה שסוגרת את מסלול המשאב, והיא בלתי-נראית
  למי שלא מנחש. (הפעולה עצמה עובדת: `voteOnMaap → {consensus: true}`.)
- כפתור "דיווח על מכירה" — אייקון בלבד, אבל **עם** `title`+`aria-label`. זו
  הדוגמה הנכונה.

### A3 · טקסט מקודד קשיח בעברית ב-`hachcal.svelte`
בניגוד לכלל ב-`CLAUDE.md`, כל הטקסטים במחשבון החלוקה כתובים ישירות בעברית ולא
דרך `$t()`: `יש להזין את סכום הרווח שנצבר…`, `טבלת חישוב`, `שם`,
`החלק מהרווח`, `אחוז בפרויקט`. משתמש ב-en/ar/ru/es רואה עברית.

## מה עבד טוב

- **יצירת ריקמה** (`createWeave`) — טופס אחד, מעבר מיידי ל-`/moach/82/main`.
- **עריכת פרטי הריקמה** (`updateProjectDetails`) — נשמר מיידית ליחיד, בלי
  הצבעה מיותרת.
- **יצירת משימה** (`createMission`) — נוצרת ישירות כ-`openMission`
  (`branch: "open"`), בלי הצבעה, כמצופה לחבר יחיד.
- **מסלול solo ב-`applyToMission`** — קיים ועובד (כשאין גרשיים בתיאור);
  יוצר `Mesimabetahalich` ישירות במקום `Ask` תקוע.
- **טיימרים** — הפעלה/עצירה/שמירה עם הערה, שעות מצטברות (0.02 / 1), וחסימה
  נכונה של סיום משימה עם זמן לא שמור ("יש זמן שלא נשמר. יש לשמור או לאפס לפני
  ההגשה") — ואז פתיחת דיאלוג השמירה. התנהגות מדויקת.
- **תצוגת שווי (EquityPreview)** — שלושת התרחישים ("לפי השווי הנוכחי" /
  "כולל מה שאושר" / "אם יאושר כל מה שפתוח") עקביים עם הנתונים, כולל אומדן
  שקלי (`≈ 499 ₪ בחודש`) עם דיסקליימר.
- **מכירה עם `holderStatus`** — ברירת מחדל "מאומת (עצמי)" בדיוק לפי
  `docs/PLAN_sale_holder_consent.md`; המלאי ירד 3→2.
- **משאב בהשמה עצמית** — נכנס ל"אספקות בתהליך", ואישור הקבלה ביחיד מגיע
  לקונצנזוס מיידית ויוצר `rikmash`.
- **דף התמיכה הציבורי** — מדד הכיסוי מדויק (שווי ₪2 · הכנסות ₪500 · חולק ₪0 ·
  זמין ₪498) וגם מכבד את מתג "כבוי" עם באנר לחבר הריקמה.
- **קאנבן / גאנט / שרשראות / עמוד אובייקטים לפי סוג** — נטענים ומשקפים נכון
  את המצב.
