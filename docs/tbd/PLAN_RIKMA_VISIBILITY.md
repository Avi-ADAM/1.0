# PLAN_RIKMA_VISIBILITY — מי רואה רקמה ומוצר, ואיפה קונים

**מצב:** תכנון, שום דבר לא נבנה. נכתב 2026-11-11, על בסיס קריאת הקוד בלבד.

## 1. הבעיה

היום כל רקמה וכל מוצר גלויים בריכוזים הציבוריים, וכל מוצר נמכר דרך מסלול הרכישה שלנו.
צריך לאפשר שלושה דברים נוספים:

1. **רקמה שמתנהלת רק בין השותפים** — לא מופיעה בריכוזים.
2. **מוצר מוסתר** — למשל כשמוכרים אותו רק מהאתר של הרקמה, עם הסליקה שלה.
3. **מוצר גלוי שנקנה אצלם** — במקום "לרכישה" שלנו, "לרכישה באתר" שמפנה החוצה.

ובנוסף: בעמוד המכירות ב-moach, כפתור "לצפייה באתר" ליד כל מוצר.

למי שמוכר רק מהאתר שלו, ולכן לא משנים את זה.

## 3. המודל

שלושה צירים עצמאיים. לא מאחדים אותם לשדה אחד.

### 3.1 `Project.visibility` — האם הרקמה מופיעה

`public | unlisted`. **null = legacy = public**, כמו שאר השדות שנוספו לרקמה.
enum ולא boolean כדי שאפשר יהיה להוסיף `private` בלי מיגרציה.

`unlisted` אומר: לא מופיעה בשום ריכוז, לא מוצעת לזרים, לא נסרקת. **קישור ישיר עדיין עובד**,
כי הזמנות, עמודי הצטרפות ותמיכה נשענים עליו. זו לא סודיות, וה-UI צריך לומר את זה.

ההסתרה יורדת במדרג: משימות פתוחות, משאבים פתוחים ומוצרים של רקמה `unlisted` יורדים איתה
מהריכוזים, גם אם `hideFromDiscovery` שלהם false. בלי זה שם הרקמה נחשף בכרטיס של כל משימה.

### 3.2 `Matanot.hideFromDiscovery` — קיים, נשאר

הרחבה אחת: לא מוצג למי שאינו חבר בעמוד הרקמה הציבורי, ו-noindex ב-`/gift/<id>`.

### 3.3 `Matanot.buyMode` + `Matanot.externalBuyUrl` — איפה קונים

`buyMode`: `platform | external`. **null = legacy = platform**. `external` מחייב `externalBuyUrl`.

| `hideFromDiscovery` | `buyMode` | התוצאה |
| --- | --- | --- |
| false | platform | ברירת המחדל של היום |
| true | platform | לא בריכוז; נקנה אצלנו בקישור ישיר |
| false | external | בריכוז; הכפתור "לרכישה באתר" יוצא החוצה |
| true | external | לא בריכוז; בקישור ישיר הכפתור יוצא החוצה |

## 4. כללים שחייבים להישמר

1. **קישור רכישה חיצוני עובר הסכמה.** את המתג הקיים כל חבר הופך לבד, וזה בסדר לתצוגה. קישור
   רכישה זה אחרת: חבר אחד היה יכול להפנות את הקונים לסליקה הפרטית שלו. לכן `buyMode` ו-`externalBuyUrl`
   הם **תנאים** ב-`editObject`, כמו מחיר. רקמה של חבר אחד ומוצר אישי — ריבוניים, חלים מיד.
2. **הכפתור הציבורי מוביל רק לכתובת שאושרה.** אין נפילה ל-`linkToWebsite` במסלול הקנייה, כי
   אותה כתובת נכתבת בלי הסכמה. בטופס היא רק ממלאת ברירת מחדל, ומה שנחתם הוא הכתובת המדויקת.
   הכפתור הפנימי ב-moach (חברים בלבד) כן נופל ל-`linkToWebsite`.
3. **שינוי `visibility` עובר החלטת רקמה** (הוחלט, §7 D1), בשני הכיוונים: `Decision kind:'rikmaVisibility'`.
   שתיקה עד `restime` מאשרת, הצעה נגדית היא הערך השני ומאפסת את השעון, אין דחייה, יש צ'אט.
4. **מכירה חיצונית לא נרשמת מעצמה.** אין `Sale`, אז אין חלוקה ואין חלק לאתר עד שמישהו מדווח.
   זה נאמר לשותפים בעמוד ההצעה, לפני שהם חותמים, ובעמוד המכירות.
5. **קריאה לפי מפתח לא מושפעת.** חנות מחוברת ממשיכה לקרוא ולדווח גם כשהרקמה `unlisted`.
   החסימה לאנונימיים בלבד, כמו `isHiddenProject` היום ב-`api/v1/r/[rikma]`.
6. **אימות כתובת בנקודה אחת**, פונקציה טהורה `normalizeExternalUrl`: מוסיפה `https://` לדומיין
   חשוף, מקבלת http/https בלבד, בלי פרטי התחברות בכתובת, עד 500 תווים. קישור מוצג עם
   `target="_blank" rel="noopener noreferrer nofollow ugc"`.
7. **ליד כפתור חיצוני שורה גלויה:** הרכישה מתבצעת באתר הרקמה ולא ב-1lev1.

## 5. משטחים להסתרת רקמה

פונקציה אחת: `isHiddenRikma(projectNode)` ב-`$lib/server/discovery/` — הרשימה הקשיחה **או**
`visibility === 'unlisted'`. כל קריאה ל-`isHiddenProject` על צומת רקמה עוברת אליה, וכל qid מהרשימה
בוחר גם `visibility`.

סינון אחרי הטעינה ולא ב-GraphQL: מסנן על `projectcreates` היה מוריד מוצרים אישיים בלי רקמה.
מוצר שתלוי בכמה רקמות מוסתר אם **אחת** מהן מוסתרת, כדי לא לחשוף את שמה.

| משטח | qid / קובץ | היום |
| --- | --- | --- |
| `/project` | `281discoverProjects` | מסונן ברשימה הקשיחה |
| `/availableMission` | `283discoverMissions` | מסונן |
| `/availiableResorce` | `284discoverResources` | מסונן |
| `/gift` | `282discoverProducts` | מסונן |
| חיפוש קטלוג (סוכן, MCP) | `conciergeTools.ts:75` | מסונן |
| `getProjectDetails` | `projectDetailsTools.ts:165` | מסונן |
| API ציבורי אנונימי | `api/v1/r/[rikma]/*`, `shippingRoutes.ts` | מסונן |
| backfill תרגום | `backfillSources.ts` + `318`, `319` | מסונן |
| מפה, `/demand`, `/api/map-data`, sitemap | `loadMapData.ts` (`221`, `222`, `269`) | **לא מסונן בכלל** |
| מוני ה-hub | ה-qids של הספירה | **לא מסונן**; לבדוק אם שווה לטפל |
| הצעות התאמה ומיילים | `matching/engine.ts` (`203matchOpenMissionsForUser`, `206…`, ההקשר ב-`200`, `204`) | **לא מסונן** |
| רקמות קרובות | `matching/nearbyRikmas.ts` | **לא מסונן** |
| מוצר למשאלה | `203findMatanotByText` | מסנן מוצר, לא רקמה |
| פרופיל משתמש | `user/[id]` (`52GetUserById`) | **לא מסונן**; להסתיר ממי שאינו חבר |
| `/r/<slug>`, `/project/<id>`, עמודי משימה / משאב / מוצר של רקמה מוסתרת | | נשארים פתוחים, מוסיפים `noindex` |

עמוד אירוע (`/r/<slug>/e/<event>`) נשאר ציבורי: הרקמה פרסמה אותו במפורש.
הצעה של רקמה מוסתרת על משאלה חושפת את שמה למשאלה הזו, גם זה מעשה מכוון שלה.

**מה ההסתרה לא עושה:** לא מוחקת מה שכבר נסרק (noindex נקלט בקצב הסריקה של גוגל), וה-sitemap
נשמר במטמון עד שעה. תרגומים שכבר נקנו נשארים במטמון.

## 6. שלבים

### S0 — כפתור "לצפייה באתר" (קוד בלבד, Vercel)

- `normalizeExternalUrl` + בדיקות.
- `linkToWebsite` מגיע ל-`Hamatanot` מ-`sales/+page.svelte`.
- כפתור בשורת המוצר, ליד "עריכה" (`hamatanot.svelte:784`), וגם ברשימת `sales/manage/products`. בלי כתובת — לא מוצג.
- מפתחות ב-`project.hamatanot.*`, חמש שפות.
- תיקון אגב: `support/+page.svelte:244` משתמש בכתובת גולמית. דומיין בלי `https://` נשבר שם לקישור יחסי.

### S1 — סכמה ב-1.0b

- `Project.visibility`.
- `Matanot.buyMode`, `Matanot.externalBuyUrl`.
- `Decision.kind` += `rikmaVisibility`, ושדה הערך המוצע.
- `negoarch` += `buyMode`, `externalBuyUrl`.
- `npm run types:update`, `validate:qids`, `check:translatable` (הכתובת אינה טקסט לתרגום).

### S2 — הסתרת מוצר עד הסוף (קוד בלבד)

- סינון `hideFromDiscovery` ב-`RikmaPage.svelte` למי שאינו חבר. חבר רואה את המוצר עם תווית "מוסתר".
- `noindex` ב-`/gift/<id>` למוצר מוסתר.
- שורת הסבר למתג: מה הוא מסתיר ומה לא.

### S3 — מנוע ההסתרה

- `isHiddenRikma` + `visibility` בכל ה-qids של §5, כולל השורות שלא מסוננות היום.
  הסגירה הזו מתקנת גם את רקמות ה-QA שדולפות היום למפה.
- `noindex` בעמודי הרקמה, המשימה, המשאב והמוצר.
- ב-matching: לא נוצרות הצעות ומיילים לזרים. הזמנת שותף ישירה (`partnerInvite`) ממשיכה לעבוד.

### S4 — החלטת הרקמה

לפי התבנית של `promoPolicy`:

- פעולות `proposeRikmaVisibility`, `counterRikmaVisibility`. רקמה של חבר אחד חלה מיד.
- ענף ב-`voteOnDecision`, הבשלה בשתיקה דרך timegrama, כתיבת `visibility` בהבשלה.
- כרטיס בלב (`LevCard`, כולל תצוגות list/cards/coins), פורום, והתראה עם משפט ושני קישורים.
- UI בהגדרות הרקמה: מצב נוכחי, מה ייעלם ומה יישאר, כולל "קישור ישיר עדיין עובד".
- `INLINE_NOTICE_KINDS`, `actionClient.ts`, `qidsAccess.js`, `access` של הפעולות.

### S5 — הגדרת רכישה חיצונית

- בעורך המוצר (`shopProductEditor`, `productEditor.ts`): בחירת מסלול וכתובת. ברירת מחדל מ-`linkToWebsite`.
- `buildRound`, `hasAnyChange`, `roundFragment`, `applyObjectChange`: לשאת את השדות.
  **`vote.ts` כותב מחדש את כל הסבבים בהצעה נגדית**, אז שדה שלא ב-`roundFragment` נעלם בשקט.
- עמוד ההצעה מציג את הכתובת המלאה ואת ההערה על הדיווח (§4.4).

### S6 — מסלול הקנייה

- `/gift/<id>`: במצב `external` כפתור יוצא במקום `handleBuyNow`, בלי טופס ובלי מונה מלאי.
- `/gift`, `RikmaPage`: תווית "נקנה באתר הרקמה".
- **חסימה בשרת, לא רק ב-UI:** `createSheirutpend` הוא היום qid ישיר בלי בדיקה של מצב המוצר. צריך לעטוף אותו
  ולהחזיר `PRODUCT_SOLD_EXTERNALLY` למוצר `external`. בקשות רכישה פתוחות נשארות תקפות.
- `203findMatanotByText`: לא מציע מוצר `external` למסלול הפנימי של משאלה.
- עמוד המכירות: תג "נמכר באתר" ותזכורת לדיווח, עם קישור ל"דיווח מכירה" הקיים.

### S7 — API ו-MCP

- `dto.ts`: `buyUrl` הוא `externalBuyUrl` במצב `external`; שדה `buyMode` חדש (רשימת השדות המותרים ובדיקות ה-DTO).
- `checkout` לא משתנה: החנות היא הקופה ומדווחת ב-`POST /orders`.
- `getRikmaProductTool` מחזיר את המסלול. `proposeProductEditTool` ו-`proposeProductEditsBatchTool` מקבלים
  את השדות, כדי שחנות עם הרבה מוצרים לא תזין אותם אחד-אחד. לבדוק איך batch נחתם.

### S8 — QA

שני משתמשים אמיתיים (1/2), רקמה משותפת:

- הצעת הסתרה, הבשלה בשתיקה, והיעלמות מכל שורה ב-§5 כשצופים כאורח וכזר מחובר.
- הצעה נגדית שמחזירה ל-`public`.
- מפתח API ממשיך לעבוד על רקמה מוסתרת, אנונימי מקבל 404.
- קישור חיצוני: חתימה, כפתור, ניסיון ישיר ל-`createSheirutpend` שנחסם, דיווח מכירה ונכנס לחלוקה.
- `npm run check`, `npm test`, `check:i18n`, `check:script`, `validate:qids`, `check:proxy`.
