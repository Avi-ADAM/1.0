Connecting an AI agent to 1lev1 over MCP

How a partner platform's agent acts for its user on 1lev1: find partners, draft a partnership, apply to an opening, and read contributions and ownership. One remote MCP server, standard OAuth, no SDK.

2Vocabulary in one minute

rikmaA partnership (Hebrew for living tissue, and for embroidery). In the API it is a project.
missionWork a partner takes on that earns a share. Open (looking for someone) → in progress (hours logged) → finished (hours approved).
resourceSomething a partner brings: equipment, money, a service, a space.
decisionAnything that needs the partners' consent. Each has a clock (restime) the rikma sets.
sale / splitIncome of the rikma, and its distribution between partners by their shares.

3Connect

OAuth (recommended for a platform). The server follows the MCP authorization spec, so a compliant MCP client needs no custom code.

  1. Discover: GET https://api.1lev1.com/.well-known/oauth-protected-resource/api/mcp names the authorization server. Its metadata is at /.well-known/oauth-authorization-server.
  2. Register the client: POST /oauth/register with your redirect URIs. [TODO: confirm partner redirect hosts are accepted (partner registry)]
  3. Authorize: send the user to /oauth/authorize with code_challenge_method=S256. The user signs in (or signs up) and sees a consent screen in their language.
  4. Exchange the code at /oauth/token, then call the server with Authorization: Bearer <token>.

Personal key (fastest way to try it). A member creates a key under Settings → API keys, or runs npx 1lev1-mcp, and the client sends it as the bearer token. [TODO: sandbox key for the demo rikma, if issued]

# List the tools
curl -s https://api.1lev1.com/api/mcp \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# Search open missions that mention video editing (same headers)
curl -s https://api.1lev1.com/api/mcp ... \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{
        "name":"searchCatalogTool",
        "arguments":{"query":"video editor","kinds":["missions"],"limit":5}}}'

5The consent model (what an agent can never do)

  • The agent prepares, a person confirms. Creating a partnership, accepting an offer, approving a vote, a sale or a profit split is always the person's own click on 1lev1. No tool does it for them.
  • There is no hard "no". Partners approve, open a discussion, or counter-offer. An agent should never reject something on a user's behalf.
  • Silence is consent, on the partners' clock. An open proposal is approved when the rikma's response time runs out. getMyUpdatesTool returns the deadline and whether silence approves, so the agent can tell the user what will happen if they do nothing.
  • Money reads are effective-only. A sale still awaiting its holder's confirmation is not reported as income.
